# Step Tracker — RAG OPS

## Ingestion pipeline

| Step | Phase | Problem | Solution |
|---|---|---|---|
| Step 0.1: Project Bootstrap | Setup | Minimal setup required to bootstrap the project. | Added data generator (`scripts/generate_docs.py`) and initialized the project via `uv init` (`.venv` in place). |
| Step 1.1: Single PDF Ingestion Baseline | Ingestion | Single pipeline script with all ingestion stages (load, parse, chunk, embed). | Added `ingestion.py`. |
| Step 1.2: Text Cleaning & Metadata Extraction | Ingestion | PDF/HTML extraction leaves inline tags (`**`) and administrative header blocks inside text chunks. | Added `clean_text()` and `extract_frontmatter()`. |
| Step 1.3: Real Embedding Model | Ingestion | The pipeline uses numpy to generate random 1536-dim baseline vectors. | Replaced with a real embedding model via OpenRouter. |
| Step 1.4: Persistent Vector Store | Ingestion | `self.vector_store` is an in-memory dict (`Dict[str, EmbeddedChunk]`), so embeddings are lost when the script exits. | Integrated a ChromaDB `PersistentClient`; `upsert_to_vector_store()` persists `(id, embedding, document, metadata)` on disk and survives restarts. Added `search(query_text, top_k)`. |
| Step 1.5: Stage-Based Refactor | Ingestion | `RAGIndexingPipeline` became too big with all concerns in one class. | Split into single-purpose stages (`IngestionStage`, `ChunkerStage`, `EmbeddingStage`, `VectorStoreStage`); the pipeline is now a thin orchestrator with the same public API. |
| Step 1.6: Recursive Structure-Aware Chunking | Ingestion | Fixed-character slicing chops mid-word/mid-sentence, breaking semantic context. | Replaced with recursive splitting across paragraphs → lines → sentences → spaces; merges up to `chunk_size` with `chunk_overlap` windows (0 true mid-word cuts). |
| Step 1.7: Document Hashing & Idempotent Deduplication | Ingestion | Re-running ingestion re-chunks, re-embeds (OpenRouter costs), and duplicates data in ChromaDB. | Adds SHA-256 content digest in metadata; unchanged docs are skipped, changed docs get stale chunks purged before re-indexing. |
| Step 1.8: Robust PDF Parsing (Tables + Scanned OCR) | Ingestion | Standard `pypdf.PdfReader` collapses complex table grids into scrambled strings and returns blank text on scanned PDFs. | Upgraded to `pdfplumber`: text plus tables converted to clean Markdown grids; blank/scanned pages fall back to OCR (`pdf2image` + `pytesseract`) when available. |
| Step 1.9: Production Hardening (Logging, Retries, Error Isolation) | Ingestion | `print()` leaves production failures invisible, and one broken file (429s, socket drops, corrupt PDF page) crashes the whole batch. | Replaced `print()` with structured `logging`; wrapped OpenRouter calls in `tenacity` exponential-backoff + jitter retries; added `run_batch()`/`run_directory()` with per-file error isolation. |
| Step 1.10: Modular Package Refactor (src/ layout) | Architecture | A single flat `ingestion.py` file (650 lines) is hard to evolve — new stages, CLIs, or test suites must touch one monolith. | Refactored into packages: `src/ingestion/` (pipeline + `stages/`), `src/core/` (logging, resilient retries), `src/utils/` (text cleaning, table→markdown, OCR); `uv` builds an editable wheel with `ragops` CLI; legacy class aliases keep the public API stable. |
| Step 1.11: Automated Unit & Integration Tests | Testing | "Code can break": regressions (parser changes, retry policies, dedup) had no safety net. | Added pytest suite (46 tests): unit coverage per stage plus integration tests over the full pipeline with stubbed embeddings (offline, no API cost), including idempotency, purge-on-change, batch error isolation, and Markdown table extraction; `dev` dependency group with `uv run pytest`. |
| Step 1.12: Source Abstraction & Directory Discovery | Ingestion | Only a single explicit file path can be loaded, so indexing a whole KB means calling the pipeline per file. | Added a `DocumentSource` abstraction (`source_type` = `filesystem`, future `rdbms`/`api`): `FileSystemSource` recursively scans input directories (with sub-directory categories); `pipeline.ingest_source()` ingests discovered references under per-document error isolation stamping `data_source="filesystem"`, and the `ragops` CLI now scans an input directory (`ragops [input_dir]`, default `data/raw`) end-to-end. |
| Step 1.13: Format Parity & Per-Format Parsers | Parsing | Only PDF parsing had real logic; Markdown/plain-text were handled inline in the loader, so adding a format meant touching loader code. | Added `src/ingestion/parsers/` — one `DocumentParser` per format (`pdf.py`, `markdown.py`, `text.py`) resolved by extension via `get_parser()`; renamed `document_loader.py` → `loader.py`, which now stays format-agnostic. |
| Step 1.14: Full-Code Review & Unified CLI | Architecture | Code review found `Chunker._hard_split()` hard-coding `500` instead of honoring `chunk_size`, plus a flat `main.py` and `ragops` entry point still split between two CLIs. | Fixed `_hard_split()` to use `self.chunk_size` (config-respecting); added `src/ingestion/cli.py` as the single canonical CLI (argparse flags incl. `--query`, `--top-k`, `--patterns`, `--persist-dir`) shared by the `ragops` script, root `main.py`, and `python -m ingestion.pipeline`; `FileSystemSource.discover()` now raises `FileNotFoundError` on a missing directory so the CLI exits 2 instead of silently scanning nothing. Suite grown to 69 tests. |
| Step 1.15: Centralized Configuration | Architecture | Tunables (chunk size, embedding model/URL, Chroma paths, retry policy, OCR DPI, logging, top-k) were hard-coded and duplicated across pipeline, stages, sources, CLI and utils, so values could drift (e.g. `top_k` 3 in CLI vs 5 in the search API). | Added `src/core/config.py` — a single `Settings` object of grouped frozen dataclasses, resolved with precedence code defaults < `ragops.toml` (repo root) < `RAGOPS_<SECTION>_<FIELD>` env vars; all stages/CLI/OCR/logging/resiliency now read `get_settings()`. Removed duplicated literals and unified `top_k` to 5. Suite grown to 74 tests + tests/unit/test_config.py. |
| Step 1.16: Versioned Documents & Rollback Protection | Ingestion | Bad/outdated documentation could not be removed or reverted — a content change deleted the old chunks outright, and deleted files kept surfacing with no record that they were gone. | Documents are now versioned: new files index as `version 0`, each change bumps the version, and every chunk carries `(version, is_active)` payload tags. Old-version chunks are deactivated (never deleted) and search serves only active chunks; a deleted file is marked `is_active=False` by `ingest_source`, and `pipeline.rollback(doc_id, version)` restores a previous version instantly by flipping tags. Versioned chunk IDs (`{doc}_v{n}_chunk_{i}`) prevent cross-version overwrites; a JSON `document_registry` (per collection, next to the Chroma store) records version history/liveness; authored doc `Version:` frontmatter now maps to `doc_version` so `version` stays a reserved rollback tag. Suite grown to 88 tests. |

> **Note:** The dev environment does not have the `tesseract` binary, so the OCR fallback degrades gracefully to empty output (pdfplumber handles text/tables only). Install `tesseract-ocr` to exercise the scanned-PDF path.
